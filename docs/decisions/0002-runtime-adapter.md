# ADR 0002：运行时适配层与内核的边界

- 状态：已接受
- 日期：2026-11-23
- 相关：`docs/provenance/CORE_EVALUATION.md` §5

## 背景

三件事同时成立：

1. 内核是 GPL-2.0-only。自有代码许可已定为 GPL-2.0-or-later（ADR 0003），
   组合作品可整体按 v2 分发；但**哪些文件来自上游、哪些是自有**仍须清楚可审计。
2. 内核产物是第三方代码的编译结果，其内部全局状态（`config`、`jvm`、`MIDlet` 等）不该被 UI 直接读写。
3. 旧版的桥接层是一个与第三方高度相似的私有约定，新版**不能沿用其契约结构**（规划 §2.2）。

所以需要一个既隔离许可、又隔离实现细节的边界。

## 决策

### 1. 物理分离

内核产物作为静态资源放在 `public/kernel/`，由适配器在运行时以 `script` 方式加载，**不进入 Vite bundle**。

```
产品代码 (src/**)  ──调用──▶  RuntimeAdapter  ──加载──▶  public/kernel/*.js
      ▲                                                    （独立文件，独立分发）
      └────────── 只通过接口与事件通信，不共享模块作用域 ──────┘
```

理由：GPL 的义务范围与「是否构成单一组合作品」相关。物理分离不改变法律定性（法律判断不由代码结构决定），但它让边界**可描述、可审计**：哪些文件来自上游、哪些是本项目自有，一目了然。

### 2. 契约独立设计

`src/runtime/adapter.ts` 定义的接口是本项目自行设计的，命名与语义均不继承旧版：

| 本版 | 语义 |
|---|---|
| `load(pkg)` | 载入 MIDlet 包，进入 `ready` |
| `start()` / `stop()` | 启动 / 停止并释放 |
| `pause()` / `resume()` | 暂停 / 继续 |
| `setSpeed(rate)` | 设置模拟速率，1 为正常 |
| `capabilities` | 能力声明，UI 据此决定显示什么 |
| `on(event, fn)` | 强类型事件订阅 |

设计取舍：

- **能力先行**：`capabilities` 在 `load()` 后即确定，UI 在渲染按钮前就能知道「这个内核支持不支持暂停」，而不是先显示再在点击时失败。
- **不支持就抛错**，不静默忽略。静默忽略会让用户以为功能生效了。
- **状态机收敛在基类**，实现只声明迁移意图。避免每个实现各写一套状态判断。

### 3. 错误分类而非错误透传

内核抛出的异常一律包装成 `RuntimeFailure`，带 `code`。UI 只消费 `describeFailure()` 的文案，不接触原始堆栈。
理由：内核错误信息是英文且面向开发者，直接展示给用户既无意义也可能泄露路径。

### 4. Mock 是一等公民

`MockRuntime` 不是测试辅助，而是**开发期的默认实现**：UI 在没有内核的情况下也能跑通全部交互。这也让错误与超时路径可以被稳定复现（真实内核很难刻意制造超时）。

## 后果

- 适配层多了一层间接调用，每次操作都有一次 `await`。对 60fps 的渲染循环不适用 —— 逐帧数据通过事件推送，不走方法调用。
- 新增能力（如震动、截图）需要同时改动接口、实现与 Mock，成本略高。这是有意为之：能力增长必须经过契约评审。
- `public/kernel/` 尚未创建，等 F4 时落地；届时 `check:provenance` 脚本要校验「产物哈希与登记一致」。

## 未采纳的方案

| 方案 | 未采纳原因 |
|---|---|
| 直接把内核打进 bundle | 义务边界模糊，且内核体积会让首屏加载变慢 |
| UI 直接调用内核全局对象 | 无法测试、无法替换、无法描述边界 |
| 沿用旧版桥接约定 | 规划 §2.2 明确要求重新定义 |
| 用 `postMessage` 走 Worker 隔离 | 内核需要直接写 canvas 与 WebAudio，跨线程传递会引入大量代理开销；V1.0 不做 |
