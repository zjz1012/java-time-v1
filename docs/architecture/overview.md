# 架构概览

> 当前已实现 `runtime/`、`input/`、`saves/` 与最小可用的 `app/`（运行页）；
> 其余模块仍是设计意图。

## 分层

```
┌─────────────────────────────────────────────┐
│  ui/            展示组件，纯渲染与交互        │
│  app/           装配、路由、页面框架          │
├─────────────────────────────────────────────┤
│  library/       游戏库与导入                  │
│  saves/         按游戏隔离的存档仓储          │
│  input/         键位表 + PC 键盘监听           │
│  speed/         速率控制策略                  │
├─────────────────────────────────────────────┤
│  bridge/        应用层 ↔ 运行时的消息协议     │
├─────────────────────────────────────────────┤
│  runtime/       RuntimeAdapter 契约 + 实现    │
│                        │                     │
│                        ▼                     │
│  public/kernel/  J2ME 内核产物（GPL-2.0）     │
└─────────────────────────────────────────────┘
```

**单向依赖**：上层可以 import 下层的类型与接口，下层不得反向 import。`runtime/` 不知道 `ui/` 存在。

## 各层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| `ui/` | 渲染、事件绑定、无障碍 | 业务判断、存储、内核调用 |
| `app/` | 页面装配、生命周期 | 具体功能实现 |
| `library/` | 导入校验、列表与筛选、最近游玩 | 存档读写、运行控制 |
| `saves/` | 存档 schema、隔离、ZIP 进出、配额 | 决定何时存（由运行页发起） || `input/` | 布局定义、物理键 → 逻辑控制名、卡键消解 | 把控制名翻译成设备键码（那是内核侧宿主页，见 ADR 0004） |
| `speed/` | 档位能力探测、策略选择 | 实际调速（那是 `runtime/`） |
| `bridge/` | 协议版本、消息编解码、超时 | 渲染、存储 |
| `runtime/` | 内核生命周期、能力声明、事件 | 任何产品语义 |

> 现状：外壳 ↔ 宿主页的协议暂时落在 `runtime/pluotsorbet/protocol.ts`，
> 等 `bridge/` 真的要独立支持多内核时再搬 —— 现在拆出去只会多一层空壳。

## 关键设计约束

### 1. 内核不进 bundle
见 ADR 0002。`public/kernel/` 的产物由 `scripts/build-kernel.sh` 生成，`check:provenance` 校验其与 `SOURCES.md` 登记一致。

### 2. 能力门禁
任何依赖内核能力的 UI 元素，必须在渲染前查询 `runtime.capabilities`：

```
capabilities.speedControl === false  →  不显示倍速按钮（不是灰置）
capabilities.pauseResume  === false  →  不显示暂停，只显示「退出」
capabilities.audio        === false  →  不显示音量控件
capabilities.keyInput     === false  →  不显示虚拟键区
```

理由：灰置按钮会让用户反复尝试并怀疑故障；不显示则是「本版本没有这个功能」的明确表达。

### 3. 状态只在一个地方
运行时状态由 `RuntimeAdapter` 持有，UI 通过 `statechange` 事件同步，不在组件内部维护第二份状态副本。

### 4. 存档身份用内容指纹，真相放在外壳

游戏身份不依赖文件名（同名不同包、改名同包都会出错），用 JAR 字节的 SHA-256 作为主键，
展示名只用于显示。

存档的**真相来源是外壳的 IndexedDB**，内核文件系统只是运行期缓存：启动前灌进去、
退出时读出来。原因是内核的 RMS 目录不区分游戏、且它的持久化在退出路径上会丢数据
（实测见 `kernel-contract.md` §14）。这条约束把「存档」从 UI 功能变成了运行时契约的
一部分 —— `LoadOptions.restore` 缺省等于空快照，也就是清空内核里现有的 RMS。
